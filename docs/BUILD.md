# Build and release

Requirements: JDK 17 or 21, Python 3.11+, Android SDK platform 36 and build-tools 36.0.0, NDK 28.2.13676358 and CMake 3.31.6, network access for the first dependency preparation. Set `JAVA_HOME` and `ANDROID_HOME`, or create an untracked `local.properties` with `sdk.dir`. Gradle 8.13 and AGP 8.10.1 are pinned.

## Portable debug build

```sh
python tools/bootstrap_runtime.py --portable
python tools/localization/release_generate.py
python tools/check_device_catalog.py
python tools/check_license_bundle.py
./gradlew :app:assembleDebug :app:lintDebug -Pportable=true
```

On Windows use `gradlew.bat`, or `./build.ps1 -Portable`. All interface resources are in the APK; Play Core is not required. `--portable` avoids downloading the large upstream QNN demo APK. The official GenieX AAR supplies Java API classes only; Qualcomm native runtimes are excluded. LiteRT-LM Java and native dependencies are entirely excluded from portable builds. Both builds compile the pinned llama.cpp commit using the NDK; prepare_cpu_runtime.py verifies the source archive before compiling an ARM64 CPU library with 16 KB ELF alignment. No GPU backend is used.

## NPU build

```sh
python tools/bootstrap_runtime.py
./gradlew :app:assembleNpu :app:assembleNpuAndroidTest -PtestBuildType=npu
```

The `.npu` application ID is retained to update existing device-test installations without deleting models. This debug build is not the public release identity. Native libraries are pinned by SHA-256, fetched from upstream distributions, and regenerated by the bootstrap. No model weights except Silero VAD are bundled. Source files for the integration are public; upstream native components have their own build systems and licenses. The application can be built from a clean export using pinned binary dependencies. Bit-for-bit APK reproducibility has not been established, and this repository does not compile all vendor native code from source.

The full build's Microsoft JNI binding changes only its ELF `OrtGetApiBase` symbol-version requirement to match sherpa ORT 1.28.2/C API 28. Tests cover that integration on the recorded device. Portable builds use unmodified upstream runtime artifacts and avoid this binding adjustment.

## Signed beta

Provide these environment variables from a private directory or CI secrets:

- `CAPTION_KEYSTORE`: absolute keystore path
- `CAPTION_STORE_PASSWORD`, `CAPTION_KEY_PASSWORD`
- `CAPTION_KEY_ALIAS`

```sh
./gradlew :app:assembleRelease -Pportable=true
```

Omit `-Pportable=true` for a local full NPU release candidate. See [the current distribution review](NPU-DISTRIBUTION.md): some prebuilt component/source mappings remain unresolved, so this does not produce a license-cleared public NPU release. Release builds are non-debuggable and fail if signing credentials are absent. The stable public application ID is `com.localcaption.instant`. Never publish a debug key as a release key.

Windows maintainers can run `. ./tools/signing.ps1 -Initialize` once, and `. ./tools/signing.ps1` in later shells. It keeps the key and password outside the repository under the current user's private `.codex/secrets/instant-caption` directory with restricted ACLs. **Back up both the keystore and recovery password securely before the first public release.** Losing the key prevents future updates under the same signing identity. This script does not upload the key or create an external backup.

Android cannot update a differently signed app under the same package ID. The existing `.npu` test installation stays separate from the public app. Import models through the document picker when migrating; do not uninstall an old installation until needed files are safely copied. A formal build and its portable counterpart share a signing identity and package so they can replace each other, subject to version code.

## Prepare a clean source archive

```sh
python tools/export_source.py
```

The allowlist excludes native/model caches, local paths, device logs, private audio fixtures, APKs, signing material and backups. It includes app code/resources, small bundled VAD, model catalogs, licenses, wrapper and CI configuration. Inspect `dist/source-manifest.json` and the archive before uploading. No tool here creates a GitHub repository or publishes a release.

## Package verification

Use `apksigner verify --verbose --print-certs` and `zipalign -c -P 16 -v 4`, and run `python tools/check_apk.py path/to.apk`. The latter checks native ELF load alignment and rejects Qualcomm native libraries in a build labeled portable. A 16 KB alignment check is not a substitute for running on a 16 KB-page Android device.

NPU bootstrap also pins QNN 2.51.0 and LiteRT-LM 0.18.0 / LiteRT NPU dispatch 2.3.0. The LiteRT-LM POM pins Kotlin 2.4.0, coroutines 1.11.0 and Gson 2.14.0. AGP 8.10.1 lint emits Kotlin metadata-version diagnostics for these dependencies; app Java compilation and lint completion are checked separately. No Play Services dependency is used. Catalog maintenance commands are documented in COMPATIBILITY.md.

NPU bootstrap also retains vendor AndroidManifest.xml declarations in small manifest-only AARs. These declare optional MediaTek Neuron and Tensor Edge TPU system libraries; omitting them can block access on Android 12+. Portable builds do not include these vendor AARs or native plugins.
